# Implementation coverage

This document compares the repository with **AI Workspace Browser Product Specification v1.0**. The specification is broader than the current application. This build is a working Electron workspace browser with local persistence, shared automation commands, reference captures, and text model connections. It is **not a completed implementation of every product requirement**, a protected credential broker, or an autonomous agent runtime.

Status terms below: **Implemented** means the described bounded behavior exists; **Partial** means part of the section exists with listed gaps; **Not implemented** means the capability is unavailable. Presence in the product specification does not imply a shipped feature.

## Architecture and actual boundaries

- Electron/Chromium renders remote pages in sandboxed `WebContentsView` instances with Node integration disabled and context isolation enabled. The trusted application renderer has a narrow preload API, sender/frame checks, and no direct Node integration.
- Workspaces use separate persistent Chromium session partitions. Switching a tab's workspace opens a fresh page in the destination partition; it does not transfer session credentials or live JavaScript state.
- `commands.js`, `workspace-commands.js`, and `provider-commands.js` define validated commands shared by GUI, CLI, MCP, and REST. Administrative operations are restricted to the trusted human GUI. The bootstrap API token retains broad automation access. Human-issued client tokens now have read/record-write/tab-control scopes, workspace restrictions, expiry and immediate revocation. The shared dispatcher rechecks grants and resolves targets before execution.
- Browser tools can inspect pages and run JavaScript. They must be treated as powerful account access when an authenticated page is open. Denying raw cookie commands to automation does **not** make DOM, evaluation, screenshots, or authenticated-account activity secret-safe.
- Built-in model chat sends text to the selected endpoint. Optional OpenAI-compatible read-only tools require model capability plus explicit request consent, are scoped to the conversation workspace and selected tab, and are limited to five calls. Chat cannot interact with pages, execute workflows, use image input, stream tokens, or run autonomous tasks. Cloud inference occurs at the selected remote provider; local connection failures never select a cloud fallback.
- The OS may protect saved model keys through Electron `safeStorage`. The app rejects plaintext fallback storage for keys and also supports named environment variables. This protects stored keys under the OS's assumptions; it does not isolate them from an attacker controlling the host or app process.

## Data handling and recovery limits

Project metadata is stored in `workspace-data/workspace.sqlite` (with its WAL) beneath Electron's user-data directory, and capture/file bytes in `workspace-data/components/`. Model connection metadata and encrypted key blobs use a separate file. Chromium session data resides in its own partition storage. The database, components, search index, backups and recovery copies are **not encrypted at rest**. Files are written with restrictive requested permissions where supported, but host filesystem/OS permissions remain relevant.

Each stored material is limited to 10 MiB, each PNG capture to 20 MiB, each component file to 32 MiB and each record document to 64 MiB; the project as a whole is bounded by disk space rather than a fixed store cap. Metadata changes rewrite only the changed rows; component files are never rewritten. JSON imports are limited to 100 MiB (the GUI accepts files below 50 MiB) and REST requests to 1 MiB, so larger projects use human-only package folders (`workspaces.exportPackage`/`workspaces.importPackage`). One Weft process owns a profile at a time; concurrent independent writers are refused rather than merged.

Export excludes configured provider keys, Chromium sessions/cookies, model settings, and global site rules. URL metadata removes known sensitive parameter names and fragments. This is not comprehensive secret detection: user-authored notes, URL path segments, ordinary query values, copied files, transcripts, and screenshots may contain sensitive information. Inspect exported content before sharing it. Optional exact-term residue scanning reports found/clean/unverifiable and treats PNGs/unsupported binary formats as unverifiable; it is not automatic redaction. See [local storage and export safety](STORAGE-SAFETY.md) for lock recovery, schema upgrades, conflict warnings, and tested limits.

An import never writes a path from its input. Stored file names are reduced to basenames; source HTML is retained as plain text; PNG base64 is normalized and recorded component hashes must match. Import rejects malformed supported fields and rolls back project state on failure. It creates new IDs and resets site rules/workflows to inactive, and its report lists every lossy mapping. Project duplication uses the same import pathway. The application keeps verified automatic and manual local backups; restore verifies first and preserves the replaced data under `recovery/`, and `weft store restore` works offline when the database cannot be opened. Backups share the profile's disk. Corrupt, newer or conflicting stores are preserved unchanged. See [local storage safety](STORAGE-SAFETY.md).

## API contract and live events

Authenticated `GET /v1/openapi.json` publishes an OpenAPI 3.1 document generated from every canonical command's JSON schema. `POST /v1/execute` uses a discriminated command envelope; the published alternatives preserve each command's input requirements. Human-only operations remain listed for discovery but cannot be authorized by an automation token.

Authenticated `GET /v1/events` provides live server-sent events. Supply the bearer token in the HTTP authorization header; URL tokens and browser-origin EventSource access are unsupported. Events use a strict metadata allowlist: event type, known command, human/automation/scoped-client actor, success/failure, stable workspace/target IDs, tab ID, and state version. They do not contain command arguments, results, errors, page URLs/titles, provider messages, or screenshots. The event stream is not an audit transcript or proof of an external action's success. Scoped clients receive only authorized workspace events; expiry/revocation ends streams. It does not replay missed events. Consumers should read current state after reconnecting.

The server limits concurrent event subscribers to 16, emits heartbeat comments, disconnects slow consumers, and unsubscribes closed connections. When the server is used without a shared application subscription callback, only commands executed through that server produce events.
