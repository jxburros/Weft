# Command reference

Generated by `node scripts/command-reference.js` from the shared catalog. Do not edit the table.

REST, CLI, MCP and GUI IPC use a version 1 outcome: `{schemaVersion, command, status, execution, validation, review, workspaceId, tabId, normalized, request, result, error}`. `status` is the stable outcome taxonomy (`succeeded`, `partial`, `blocked`, `approval_required`, `stale_state`, `conflict`, `unsupported`, `invalid`, `cancelled`, `timed_out`, `failed`): `partial` means the command completed but its result reports incompleteness (`result.status: "partial"`, `partial: true` or `complete: false`); failures derive it from the error code (table below), identically on every surface. When the command reached the shared dispatcher, `request` echoes the authenticated linkage `{apiVersion, requestId, actor, clientId, taskId, deadlineMs}` (a request rejected by transport-level validation omits it). Execution is `succeeded`, `failed`, `cancelled`, `not_started` or, only after a deadline expired while a command was still running, `uncertain`; validation is `passed`, `failed`, or `not_run`. Review is `required` on authority denial or a pending approval and `not_required` otherwise; it never claims human approval. Denials by the shared authority gate have execution `not_started` and an inspectable `error.details.authority` (`decision`, `reason`, `actionClass`, `level` and, for approval requests, `approvalId`, `fingerprint` and `expiresAt`). Null resource IDs mean no resource was resolved. Commands called with `requestId` also return `idempotency: {requestId, replayed}`. The GUI preload and client.execute unwrap results for compatibility; executeOutcome exposes the full contract.

Errors include a stable code, message, field, schema lookup and, when relevant, allowed values, suggestions and a list of field issues. Invalid values are not echoed. CLI emits the entire outcome as JSON on stdout, including failures: exit 0 success; 2 invalid input/unknown command/ambiguous target; 3 stale state/lease conflict/request ID conflict (`idempotency_conflict`, `already_committed`) or unresolved uncertain task work (`duplicate_risk`: reconcile it, or a person retries with `confirmDuplicateRisk: true`) or a busy shared resource (`resource_busy`: retry after `error.details.busy.retryAfterMs`) or payment terms or merchant that changed since approval (`terms_changed`, `merchant_changed`: nothing was clicked; propose again); 4 authority denial, an exhausted grant budget (`budget_exhausted`; a person renews the grant) or site_blocked (a site rule or security intelligence stopped the navigation; structured `error.details.blocked`; only a human can grant an exception); 5 approval required (retry the identical command after a human approves it in the Weft window); 6 cancellation/emergency stop; 7 timeout/deadline_exceeded/unavailable/transport failure; 8 unsupported capability (for example image input or a context window the selected model lacks; details name the capability); 9 locked (workspace encryption is locked; `error.details.reason` says why; only a person can unlock it in the Weft window, so stop and ask rather than retrying); 1 other failure. REST uses 400 invalid input, 401 unauthenticated, 403 denial, site_blocked or approval required, 404 missing target, 409 conflict/cancellation, 413 oversized request, 415 unsupported media type, 422 unsupported capability or other command failure, 423 locked, 429 busy resource or exhausted budget, 503 unavailable, 504 timeout. A transport timeout does not prove a remote action failed; inspect state before retrying consequential work. A caller deadline (REST `Weft-Deadline-Ms` header or `deadlineMs` body field, CLI `--deadline-ms`, MCP `deadlineMs` tool argument; at most 600000 ms) returns `deadline_exceeded` with `details.started` and `details.effect` (`not_started`, `rolled_back`, `stopped` or `uncertain`).

Normalization rewrites `tabs.open` to `tabs.new`, recognized top-level snake_case fields to camelCase, and `href` to `url` only for tabs.new/page.navigate. Every rewrite appears in `normalized: [{from,to}]`. Conflicting aliases are rejected; values, unknown fields and nested free-form data are never coerced.

MCP advertises ten tools: weft_tabs, weft_page, weft_workspace, weft_records, weft_memory (learned memory and background learning controls), weft_knowledge (shared collections, linked sources, services, citations, freshness and conflicts), weft_artifacts, weft_browser, weft_models and weft_reference. Grouped calls use `{action: "canonical.command", args: {...}, deadlineMs?}`; reference uses `{command: "canonical.command"}` or no arguments for an index. Existing underscore command tool calls remain accepted but are not advertised. Results include structuredContent and the same JSON text envelope; screenshots also include native image content. Mixed read/write groups conservatively advertise destructive/read-only hints; the reference exposes exact per-command metadata. MCP resources (`resources/list`, `resources/read`) expose `weft://capabilities`, `weft://guide/{topic}`, `weft://reference/commands[/{command}]` and read-only `weft://workspaces/{workspaceId}/{collection}[/{id}]` records within the token's scope.

Collection commands marked pageable accept `page: {limit, cursor}` and then return `{items, nextCursor, total}` in a stable order (creation order; history, approvals and downloads newest first); without `page` they return the unpaged list as before. Cursors are opaque and bound to the command, workspace and filters. `weft.capabilities` (also `GET /v1/capabilities`) reports the API version, catalog hash, outcome table, limits and features.

Human-only describes an unconditional administration gate. Every other non-human command passes the shared autonomy gate (see docs/decisions/005-agent-authority-and-audit.md): it may run automatically, run under a standing or one-time human approval, wait for approval in the single approval queue, or be refused by client scope, destination, data class, usage limit, autonomy level, state or content policy. Per-command data classes, resource, effect and sensitive outbound categories are available from `GET /v1/commands` and `weft_reference`. GUI controls expose a subset; trusted IPC can invoke every catalog command. Native window layout is a separate trusted IPC channel.
