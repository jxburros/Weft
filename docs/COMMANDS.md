# Command reference

Generated by `node scripts/command-reference.js` from the shared catalog. Do not edit the table.

REST, CLI, MCP and GUI IPC use a version 1 outcome: `{schemaVersion, command, execution, validation, review, workspaceId, tabId, normalized, result, error}`. Execution is `succeeded`, `failed`, `cancelled`, or `not_started`; validation is `passed`, `failed`, or `not_run`. Review is `required` on authority denial or a pending approval and `not_required` otherwise; it never claims human approval. Denials by the shared authority gate have execution `not_started` and an inspectable `error.details.authority` (`decision`, `reason`, `actionClass`, `level` and, for approval requests, `approvalId`, `fingerprint` and `expiresAt`). Null resource IDs mean no resource was resolved. Commands called with `requestId` also return `idempotency: {requestId, replayed}`. The GUI preload and client.execute unwrap results for compatibility; executeOutcome exposes the full contract.

Errors include a stable code, message, field, schema lookup and, when relevant, allowed values, suggestions and a list of field issues. Invalid values are not echoed. CLI emits the entire outcome as JSON on stdout, including failures: exit 0 success; 2 invalid input/unknown command/ambiguous target; 3 stale state/lease conflict/request ID conflict (`idempotency_conflict`, `already_committed`); 4 authority denial or site_blocked (a site rule or security intelligence stopped the navigation; structured `error.details.blocked`; only a human can grant an exception); 5 approval required (retry the identical command after a human approves it in the Weft window); 6 cancellation/emergency stop; 7 timeout/unavailable/transport failure; 8 unsupported capability (for example image input or a context window the selected model lacks; details name the capability); 1 other failure. REST uses 400 invalid input, 403 denial, site_blocked or approval required, 404 missing target, 409 conflict/cancellation, 422 unsupported capability or other command failure, 503 unavailable, 504 timeout. A transport timeout does not prove a remote action failed; inspect state before retrying consequential work.

Normalization rewrites `tabs.open` to `tabs.new`, recognized top-level snake_case fields to camelCase, and `href` to `url` only for tabs.new/page.navigate. Every rewrite appears in `normalized: [{from,to}]`. Conflicting aliases are rejected; values, unknown fields and nested free-form data are never coerced.

MCP advertises eight tools: weft_tabs, weft_page, weft_workspace, weft_records, weft_artifacts, weft_browser, weft_models and weft_reference. Grouped calls use `{action: "canonical.command", args: {...}}`; reference uses `{command: "canonical.command"}` or no arguments for an index. Existing underscore command tool calls remain accepted but are not advertised. Results include structuredContent and the same JSON text envelope; screenshots also include native image content. Mixed read/write groups conservatively advertise destructive/read-only hints; the reference exposes exact per-command metadata.

Human-only describes an unconditional administration gate. Every other non-human command passes the shared autonomy gate (see docs/decisions/005-agent-authority-and-audit.md): it may run automatically, run under a standing or one-time human approval, wait for approval in the single approval queue, or be refused by client scope, destination, data class, usage limit, autonomy level, state or content policy. Per-command data classes, resource, effect and sensitive outbound categories are available from `GET /v1/commands` and `weft_reference`. GUI controls expose a subset; trusted IPC can invoke every catalog command. Native window layout is a separate trusted IPC channel.
