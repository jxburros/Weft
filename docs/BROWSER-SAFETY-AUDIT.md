# Browser safety audit and remaining boundaries

Verified against the October 2026 issue-remediation implementation. Reference: [AI-Server-Studio browser-tab audit](https://github.com/jxburros/AI-Server-Studio/blob/main/audits/AI-Server-Studio-Browser-Tab-Audit-2026-09-30.md), especially BT-01 through BT-09 and the blocked-action finding BT-17.

| Finding | Weft behavior and evidence |
| --- | --- |
| Redirects escape destination checks | Rules are checked at request level, not after an action returns. Chromium `onBeforeRequest` checks main frames, subframes and connection-mode subresources before contact; `will-navigate` and `will-redirect` add navigation checks. Real Chromium fixtures assert that direct navigation, HTTP redirects, link clicks (human and agent), meta-refresh, script redirects, `location.replace`, a frame navigating `top`, form POST submission and background fetch never reach the blocked routes, and that blocked agent navigations return a structured `site_blocked` outcome. See the engine-path table below. This is site-rule enforcement, not a network firewall. |
| Page popups evade policy | Native window creation is denied. A page may open a tab only within Chromium's transient-activation window after real input in that tab (five seconds, current document), while an automation action is in flight on it, or on a site the person allowed pop-ups for in that workspace (#97). The destination passes `allowedUrl` first; the tab then adopts Chromium's popup WebContents (same workspace partition, sandboxed and context-isolated preferences inherited), so `window.opener`/`postMessage`/`window.close()` work, the tab records its opener and gets no agent control, and request interception applies to everything it loads. Other popups are recorded (bounded audit per document) and offered as *Open once* (new tab, no opener) or *Always allow for this site*, both human-only. Real Chromium tests cover page-initiated popups without input, a human click popup, a delayed OAuth-style popup returning by `postMessage`, a self-closing 3-D Secure-style popup, a site allowance, blocked-rule and unsafe-protocol popups (`test/browser-security.test.js`, `test/site-permissions-browser.test.js`). |
| Web permissions granted silently or by agents | Every request reaches a browser-owned prompt tied to the top-level origin (`src/site-permissions.js`) or is denied: background, suspended, headless and agent-only tabs, embedded frames from another origin, rate-limited documents and unsupported features are denied without a prompt. Only `permissions.respond` from the trusted GUI answers a prompt; `permissions.set`/`configure`/`stop` are human-only too. The permission check handler reports a grant only for a current allow decision, so `navigator.permissions` and `Notification.permission` agree with the prompt. Screen sharing uses Weft's own source picker and never a remembered allow. Real Chromium evidence: `test/site-permissions-browser.test.js` (camera via a fake device, notifications, screen sharing on Xvfb, revoke without restart, per-workspace isolation, background/agent/headless denials, never-ask) and `test/gui-site.test.js`. Not exercised with real cameras, OS location services, or on Windows and macOS. |
| Private browsing leaks into the profile or reaches agents | Private windows (#94) use in-memory partitions (no `persist:`), are erased when their last window closes, record nothing in workspaces, deny every permission, and reserve their page ids so tab commands fail with `permission_required` (`private_window`). `test/private-window.test.js` kills the app while a private page holds a cookie, localStorage, IndexedDB and Cache Storage marker and finds the marker in no profile file. The OS (swap, crash dumps) is not covered. |
| Saved passwords reach agents | The person's password vault (ADR-020) is separate from the agent broker, and every `passwords.*` command is human-only in the catalog and refused again by the service; `test/passwords.test.js` checks REST-style automation and model-tool callers get `permission_required` with no secret in the outcome. Filling uses the broker's origin-checked fill script only into frames on the saved origin, then applies the broker's residue protections (`test/passwords-browser.test.js`). |
| Input values reach readable content | `page.readable`, `page.content`, `page.snapshot` and capture text never emit values of password, payment-card (`cc-*`), one-time-code or credential-named fields. Readable/HTML extraction runs in a Chromium isolated world, so a page that patches `Element.prototype.remove` cannot keep fields in the output; HTML also drops `<option>`, event handlers, `srcdoc` and value/token/password/secret/autocomplete attributes. Snapshots report each such field as `value: null`, `redacted: "sensitive-field"` with only `hasValue`. Screenshots and PDFs mask those fields through a user-origin stylesheet, and automation image captures are refused while such a field is focused. `test/page-observation.test.js` covers a hostile page, a same-origin `srcdoc` frame and pixel-identical masked captures. Page text that repeats a secret, cross-origin frames rendered in a screenshot, `page.evaluate` and authenticated-page access are **not** a credential isolation boundary. |
| Page-controlled title reaches authority text | Titles, snapshot names/values and other page-sourced strings are capped (titles 1,000, names 200 characters, URLs 2,048/16,384) and stripped of control and bidirectional-override characters before they reach describe/persisted titles, `page.title`, snapshots, captures or handoff records. Readable, snapshot and capture results carry `contentTrust: "untrusted"`; provider framing is maintained separately. A title never grants authority. |
| Stale or overlapping actions | Every automation mutation requires `expectedVersion` **and** that the same actor has seen that version itself (`page.inspect`, `page.snapshot` or a result describing the tab), because sequential versions can be guessed. Per-tab input is serialized: one operation runs, others fail as `tab_busy` or wait in a configurable FIFO queue (`settings.update` `automation.queueLimit`/`queueTimeoutMs`); `automation.inputConcurrency: "exclusive"` requires a lease. Native input, explicit takeover, control-mode changes and emergency stop are control boundaries: they revoke leases and raw-input permission, cancel queued input (`cancelled`), and report in-flight actions as `cancellable: false`; the interrupted command fails with `action_interrupted`. Takeovers from an agent are persisted as handoff records. |
| Click claimed complete despite blocking | Click/fill/coordinate/key input reports `submitted` with an `unverified` outcome and, for clicks and keys, waits briefly for a resulting main-frame navigation. A navigation newly blocked by a site rule or security intelligence fails the command with the same structured `site_blocked` outcome as direct navigation (HTTP 403, CLI exit 4, `error.details.blocked`) instead of being reported as done; a pre-existing blocked state no longer misattributes an unrelated action. Later page-script redirects can still occur: inspect state and evidence to verify consequential outcomes. |
| Element identity changes between inspection and action | Agents can act on `ref`s from `page.snapshot`. A ref is frame-scoped (`f<frame>e<n>`), stable for the element within its document, and accepted only if it is in the acting actor's latest snapshot taken at the current tab version with no human input since. In the isolated world the element must still be connected and keep its tag, role and accessible name (fingerprint); otherwise the action fails with `stale_state` (`element_changed`, `element_detached`, `snapshot_outdated`, `not_latest_snapshot`, `ref_not_in_snapshot`, `human_input`). URL changes are covered by the version bump on navigation. CSS selectors remain available and version-bound, but are not fingerprints. |
| Agents act outside the latest page read | Index grounding: refs outside the latest snapshot are refused. Coordinate (`page.clickAt`) and keyboard (`page.press`) input from automation is refused unless a person selects agent-drives with `allowRawInput` for that tab and the agent holds the lease; coordinates must cite a current `observationId` (snapshot or capture) whose viewport size, scroll, device scale and URL still match, otherwise `geometry_changed`. Native synthetic input is not mistaken for human takeover and does not authorize downloads. |
| Explicit control modes | `tabs.setControlMode` (human-only) frames leases as **you drive**, **assist** (a named or any agent may observe and propose handoffs, not input) and **agent drives** (a named agent, or any agent that claims). Tab descriptions expose `controlMode`, controller, running activity, queued input and the last boundary; the GUI toolbar and Tabs view show them and offer mode changes. Human ownership persists across restart; agent leases do not. Autonomy levels, approvals and client grants are enforced separately by the shared authority gate before any of these checks run ([ADR-005](decisions/005-agent-authority-and-audit.md)). |
| Browser extensions bypass site rules or egress limits | Requests whose `initiatorOrigin` is an extension are cancelled by any matching block rule (navigation or connection mode) and unless the URL matches a host the person granted that extension in that workspace; without the extension manager attached they are cancelled. Real Chromium evidence: `test/extensions-browser.test.js`. Content scripts act with the page origin and remain subject only to page policy ([ADR-007](decisions/007-extension-compatibility.md)). |
| Archived pages run code or reach the network | Resource archives come from Chromium's MHTML serializer, which drops scripts; archived HTML loses sensitive form values. The offline preview (human-only) uses an in-memory session whose `http`/`https` handlers answer only from the archive's verified components and refuse everything else, with JavaScript disabled, a `sandbox`/`script-src 'none'`/`connect-src 'none'`/`form-action 'none'` CSP on every response, cancelled renderer navigation and redirects, and refused popups, downloads and permissions. `test/archive-browser.test.js` loads hostile scripts, handlers, meta refresh, forms, links, frames and external resources and observes no execution and no request ([ADR-012](decisions/012-resource-archives-and-redaction-derivatives.md)). This is not protection against Chromium renderer vulnerabilities in image, font or CSS handling. |
| Everyday chrome becomes an agent surface (#88, #89, #96) | Shortcuts, the context menu, the print dialog, DevTools and page source are reached only from real input or the trusted GUI's IPC; none is a catalog command, so CLI, MCP, REST and model tools cannot invoke them. Agent input is dispatched natively but recorded as synthetic and never triggers a shortcut or opens the context menu. A context-menu link or image opens and downloads through `allowedUrl` (site rules, security findings) and a one-use download grant for that exact URL. DevTools are refused for the offline preview, during protected operations and on agent-driven tabs; `credentials.fill` refuses a tab whose DevTools are open, as it does an attached debugger. `view-source:` stays refused by the catalog and the address bar; source views are read-only tabs that are never saved. `test/browser-chrome.test.js` covers these in real Chromium. |
| Plugins gain ambient authority | Plugins reach core only through registry hooks; built-ins get a frozen read-only capability that re-enters the dispatcher with the caller's authority; third-party code runs in a permission-model child process with no Node, network or code-generation globals ([plugins](PLUGINS.md)). |

## Engine-path coverage for site rules (#19)

Tested in `test/browser-security.test.js` with a connection-mode rule and a
positive control on an allowed host for every row, so a passing row means the
mechanism ran and the blocked host was not contacted.

| Path | Result |
| --- | --- |
| Top-level navigation, HTTP redirect, meta refresh, script/`location.replace`, form POST, frame navigating `top`, link click | Stopped before contact; stop page shown. |
| Frames (`iframe`), images, stylesheets, `fetch`, `sendBeacon`, `EventSource` | Stopped before contact. |
| WebSocket from the page and from a dedicated worker | Stopped before contact. |
| Dedicated worker, shared worker and service worker `fetch` | Stopped before contact. |
| Popups (`window.open`, `target=_blank`) | Stopped before contact; page-initiated popups without input (and without a site allowance) are not opened at all. |
| `<link rel=prefetch>`, speculation-rules prefetch and prerender | Chromium still issues these in Electron 44 even with the `SpeculationRulesPrefetch`/`Prerender2` feature switches disabled. Weft cancels every request marked `Sec-Purpose: prefetch` for **all** destinations; rules also see them first. They never create a stop page. |
| `<link rel=preconnect>` | Observed to open no connection to the fixture host in Electron 44. Not interceptable by `webRequest`; recorded as an observation, not a guarantee. |
| `dns-prefetch` and DNS resolution generally | DNS prefetch is disabled by switch. Resolution performed by Chromium before a request is cancelled, and OS-level DNS, cannot be observed by these fixtures: **not covered**. |
| Requests from browser-external tools (an agent's own HTTP client, shell, other apps) | **Not covered.** Site rules govern Weft's Chromium sessions only. |
| Web watch checks (`src/standby.js`) and model, embedding and learning requests | **Not covered.** They are made by Weft's main process with Node `fetch`, outside the Chromium sessions, so site rules and threat intelligence are not applied to them. Watch checks send no cookies or credentials, refuse redirects and stop at 15 s or 1 MiB; the workflow steps a watch starts run under the normal rules. |

Exact-visit exceptions cover one URL in one tab visit: other tabs, other
destinations, embedded resources and redirect chains remain blocked, the
permanent rule is unchanged, and exceptions are never persisted (a restart ends
them). Security findings require an explicit risk acknowledgement.

Emergency stop uses one `AutomationAdmission` latch shared by dispatch, browser and model loops. Only trusted human/admin code can resume. Resume does not release human tab leases. The latch lasts for the running application process; restart starts a new session, and provider requests cannot survive process exit. This does not retract already delivered requests.

`autonomy.js` classifies every command and provides the pure gate; `authority.js` evaluates it in the shared dispatcher before every non-human command, with human-only floors, client grants (destinations, data classes, scopes, limits) and one durable approval queue bound to an exact command/argument/actor/target fingerprint. Approvals are resolved only in the trusted GUI; approval cannot be supplied as a command argument. Click/fill/script actions are treated as external changes because Weft cannot tell a harmless click from a submission. See ADR-005 for levels, floors and limits.

`resolveCommandTargets` freezes defaults before asynchronous dispatch. With several non-archived workspaces, automation must name workspaceId for workspace-scoped schemas and tabId for page operations/capture. Explicit record IDs resolve their owning workspace. The shared dispatcher and transport response metadata must preserve these resolved targets; they are also required for scoped client authorization.

Validation: `xvfb-run -a node --test test/browser-security.test.js` covers engine paths, popups, storage modes, launches, intelligence and downloads. `xvfb-run -a node --test test/admission.test.js test/browser-workspace.test.js` passes the pure policy/target tests and real Chromium security fixture. A display is needed for the existing native layout/screenshot assertions; Chromium's ozone headless mode can stall the fixture's animation-frame wait.

## Observation and control decisions

- Snapshots are DOM-derived semantic trees (explicit/implicit ARIA roles and accessible names) computed in a dedicated isolated world (`src/page-observation.js`). Weft does not open a remote debugging port; the only DevTools protocol use is the existing in-process `webContents.debugger` attachment for beyond-viewport screenshots. Chromium's full accessibility tree is not used, so names are an approximation of the platform accessibility API.
- Coverage is reported, never implied: cross-origin frames are listed as inaccessible (not read), and sensitive fields, pending lazy images, `aria-busy` regions, declared-versus-rendered virtualized lists, opaque canvas/media, hidden nodes and node-budget truncation are counted. Closed shadow roots cannot be detected.
- Captures default to a 4,096 px limit per side (configurable to 8,192). Regions that exceed it are cropped, not silently downscaled, and the metadata records the clip, image size, scale, device scale, zoom, viewport, scroll, document size, URL, timestamp and navigation version.
- A protected-operation flag on a tab denies every automation observation route (`page.readable`, `page.content`, `page.title`, `page.snapshot`, `page.screenshot`, `page.pdf`, `page.evaluate`, `artifacts.capture`). `credentials.fill` raises an exclusive protected operation (ADR-017): during it and a cooldown every automation command on the tab except `page.inspect`, `tabs.list` and `tabs.release` is refused (titles withheld); afterwards filled fields stay redacted, `page.evaluate` is refused on the filled document and observation is refused if the page reveals or copies the secret. `Browser.setProtectedOperation` remains for other protected flows. Covered by `test/credentials-browser.test.js`; no independent security review yet.
- `page.message` (Send to Weft) is human-only and read-only. It runs the message-capture script in the same isolated observation world, refuses non-HTTP(S) pages, is bounded to 5 s and fails with `page_changed` if the tab navigates during capture. It returns the text to the trusted GUI for review and stores nothing itself. Covered by `test/message-capture.test.js` (real Chromium, fixture pages) and `test/gui.test.js`.

Regression tests: `test/page-observation.test.js` (real Chromium: snapshots, frames, redaction, hostile pages, ref grounding, blocked clicks, region capture limits, masking, raw input permission, geometry checks, human input invalidation, takeover during an action and handoff resume) and `test/tab-control.test.js` (two scoped clients competing for a tab, FIFO queue, exclusive mode, takeover boundaries, handoff evidence/secret rejection/acceptance, control modes and protected observation).
